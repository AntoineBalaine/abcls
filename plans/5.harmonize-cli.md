## Context

While harmonizing a score (chord symbols in voice 1, melody in voice 2) with `harmonizeVoicing`, we found these shortcomings:

1. The CLI has no way to run a transform. The transforms are only reachable through the language server socket.
2. `abc-cli/dist/abcls.js` fails at startup, because `commander` cannot be resolved from the bundle.
3. `harmonizeVoicing` replaces a note by a chord with `replace(csNode, chordCsNode)` in `editor/src/transforms/harmonize.ts`, and the note's rhythm and tie are dropped.
4. The chord in effect is a single system-wide value in `ContextInterpreterState.currentChord` (`parse/interpreter/ContextInterpreter.ts`). Because the voice 1 line is written before the voice 2 line, a note in voice 2 sees the last chord of the voice 1 line, not the chord that sounds at the same time.
5. `Bb6` is parsed as a major chord with an extension of 6, and `SEVENTH_CHORD_SPECS` in `parse/music-theory/harmonization.ts` has no entry that uses the sixth, so the tool builds a major seventh chord.
6. In the `close` voicing with four voices, a lead that is not a chord tone is skipped silently.

## Decisions already taken

- The work lives on the branch `fix/harmonize-cli`, created from `feat/musicxml-layout`.
- The CLI gets a generic command `abcls transform` and a command `abcls harmonize` built on top of it.
- Chord symbols are found in any voice of the same tune when the target voice has none, aligned in time. A `--chords-from <voice>` option is not part of this plan.
- `Bb6` is a true sixth chord: Bb D F G. A `m6` quality is added as well (Cm6 is C Eb G A).

## Phase 1: keep the durations when a note becomes a chord

Because the rhythm node is a child of the note node, the replaced note takes its rhythm with it. Because the tie is a separate child (see `findTieChild` in `editor/src/transforms/treeUtils.ts`), it is lost too.

Pseudo-code, in `harmonizeVoicing` of `editor/src/transforms/harmonize.ts`, right before `replace(csNode, chordCsNode)`:

```
rhythm = findChildByTag(csNode, TAGS.Rhythm)
tie = findTieChild(csNode)
if rhythm exists
  detach rhythm from csNode, append it to chordCsNode
if tie exists
  detach tie from csNode, append it to chordCsNode
replace(csNode, chordCsNode)
```

The order of the children of a chord node must match what `fromAst` builds and what `toAst` and the serializer expect, so the first step is to read `toCSChord` and the chord shape in `csTree/types.ts`. Broken rhythm markers (`>` and `<`) live on the rhythm node and follow the same path.

Tests, in `editor/tests`: a spec per case (plain duration `F3`, fraction `F3/`, broken `D2>`, tie `E-`, no rhythm) asserting the serialized text after the transform.

## Phase 2: sixth chords

Because `parse/music-theory/chordPitches.ts` already builds sixth chords from the extension (6 adds 9 semitones), no new `ChordQuality` member is needed, and adding one would break every exhaustive `Record<ChordQuality, ...>`. The fix therefore lives in `getIntervals` of `parse/music-theory/harmonization.ts`: when the extension of the chord is 6 or 69, the entry with function 7 receives the interval 9 and the scale step 5 (the major sixth). The function stays 7 so that the voicing algorithms keep their four slots. This covers `Bb6`, `Cm6` and 6/9 chords.

Tests, in `parse/tests/harmonization.spec.ts` and `editor/tests/harmonize.spec.ts`: the intervals of `Bb6` and `Cm6`, and a close voicing with the sixth as lead.

## Phase 3: chord symbols that are shared across voices

Because the tree walk of the editor already has the rhythm arithmetic (`getNodeRhythm`), the timeline lives in `editor/src/transforms/chordTimeline.ts` and not in `parse`. It walks the tune body, keeps a (bar, offset) clock per voice, and records every chord symbol and every note, rest and chord. `chordAtNode` returns the latest chord symbol at or before a node, from any voice, and a symbol of the node's own voice wins a tie. `harmonizeVoicing` builds the timeline itself from the selection root, so neither the socket handler nor the CLI needs to pass anything. When the timeline finds no chord, the old snapshot chord is used, so the single-voice behavior is unchanged.

The walk applies tuplets (with the default q of the interpreter, `TUPLET_Q`) and broken rhythm (`getBrokenRhythmMultipliers`), both exported from `parse/interpreter/TuneInterpreter.ts` so the timeline and the interpreter share one set of rules. A barline that closes nothing is not counted, and each tune restarts the clocks. Known limit: voice overlays (`&`) and mid-tune `L:` and `M:` changes are not followed.

## Phase 4: the transform command of the CLI

Done as `abcls transform <file> <name> [args...]` with `--voice`, `--lines` and `-w`. The `--bars` option was left out. The reusable logic moved into the editor package, in `editor/src/runner/`: `transformLookup.ts`, `csTreeSerializer.ts`, `selectionRangeResolver.ts` (which now reuses `computeNodeRange` and `rangesOverlap` from `utils/rangeUtils.ts` instead of duplicating them), `transformConstants.ts`, and the new `runTransform.ts`. The server imports them from `abcls-editor`. The `explode` transforms now also select rests, so lines that hold only rests are exploded.

## Phase 5: the harmonize command of the CLI

Done as `abcls harmonize <file> --from <voice> --into <ids> [--voicing close|cluster|spread] [-w]`, built in `editor/src/runner/harmonizeVoices.ts`. It copies the melody lines into a work voice, runs `harmonizeVoicing` with the chosen voicing and then with the cluster voicing for the skipped leads, runs `explode`, drops the top part, relabels the other parts, declares the voices (bass clef for the lowest) and extends `%%score`. `harmonizeVoicing` now skips notes that are already inside a chord, so it can run twice. Only melodies written with inline `[V:id]` markers are supported.

## Phase 6: the CLI bundle

Two causes made `dist/abcls.js` crash at startup: a partial `commander` install in `abc-cli/node_modules` (no `index.js`), repaired by reinstalling, and `jsdom` bundled by esbuild through `xml2abc` (it reads a stylesheet relative to its own folder), fixed by marking `jsdom` as external and adding it to `publish-package.json`. The script `npm run test -w abcls-cli` rebuilds the bundle and runs `--help`, and it is part of the root `npm run test`.

## Phase 7: one block chord per chord symbol

Added after a first review, because harmonizing the melody (Phase 5) is a soli technique, and the aim was a chord pad under the chord symbols. The command `abcls harmonize <file> --chords-from <voice> --into <4 to 6 ids>` is built in `editor/src/runner/blockChords.ts`. For each chord line it writes a line of seed notes, with one note per chord symbol and the length of the symbol (a symbol lasts until the next symbol or the barline, and a full-bar `X` rest uses the bar length of the meter). The seed is the chord tone nearest to the previous top voice, in the register E4 to G5, written with an explicit accidental. The chord timeline of Phase 3 reads the chord of each seed from the chord voice, `harmonizeVoicing` builds the chord under it, `explode` splits the chords into parts, and every part is kept as a new voice. The new voices are written after the other voices of their system.

Known limit: the harmonizer builds seventh chords, so a plain major chord such as `Ab` comes out as a major seventh (Ab C Eb G).

## Phase 8: ties and time after the review

Because a tied melody note becomes a whole chord, the tie of the chord would join pitches that differ. `repairChordTies` in `editor/src/transforms/harmonize.ts` replaces it by ties on the notes that the next chord of the same voice (found with `nextNodeInVoice` of the chord timeline) repeats at the same place from the top, which is the place that `explode` turns into a part. The chord-line reader of `blockChords.ts` applies tuplets and broken rhythm with the same interpreter rules.

Known limit found on the way: when the lead is the root C of the chord, `buildChord` builds the chord an octave below the lead (because of the `leadMidi - 1` rule), so the lead is missing from the chord.

## Risks

- The chord timeline changes which chord a note sees. Existing specs for `harmonizeVoicing`, `parallelVoicing` and `dropVoicing` must keep passing, so the timeline is only used when the target voice has no earlier chord symbol of its own at that bar, and the old behavior is kept for the single-voice case.
- Adding enum members breaks every exhaustive `Record<ChordQuality, ...>`, which `tsc` reports.
